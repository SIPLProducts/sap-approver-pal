# 03 — PM2 Installation and Configuration

PM2 supervises the two long-running Node processes:

| PM2 app name | What it runs | Port |
|---|---|---|
| `resl-quality-app` | TanStack Start SSR app (frontend + its API) | 3000 |
| `resl-quality-mw` | SAP middleware (`middleware/server.js`) | 3005 |

---

## 1. Install PM2 globally

```bash
sudo npm install -g pm2@latest
pm2 -v
```

Global (not project-local) so the systemd boot unit can resolve it.

## 2. Install log rotation

Without this, PM2 log files grow unbounded.

```bash
pm2 install pm2-logrotate
pm2 set pm2-logrotate:max_size 20M
pm2 set pm2-logrotate:retain 14
pm2 set pm2-logrotate:compress true
pm2 set pm2-logrotate:rotateInterval '0 0 * * *'   # daily at midnight
```

## 3. The ecosystem file

Copy `deploy/quality/ecosystem.config.cjs` from the repository to
`/data/webapplication/resl_approval/Quality/scripts/ecosystem.config.cjs`.

It declares both apps, points every log at `Quality/logs/`, and loads each
process's environment from its own `.env` file:

```js
// Quality/scripts/ecosystem.config.cjs   (abridged — see deploy/quality/)
module.exports = {
  apps: [
    {
      name: "resl-quality-app",
      cwd: "/data/webapplication/resl_approval/Quality/frontend/current",
      script: "wrangler",
      args: "dev -c dist/server/wrangler.json --ip 127.0.0.1 --port 3000 --local",
      interpreter: "none",
      instances: 1,
      exec_mode: "fork",
      max_memory_restart: "1G",
      env: { NODE_ENV: "production", PORT: "3000", CI: "1" },
      out_file: "/data/webapplication/resl_approval/Quality/logs/app-out.log",
      error_file: "/data/webapplication/resl_approval/Quality/logs/app-err.log",
      time: true,
      autorestart: true,
      restart_delay: 3000,
      max_restarts: 10,
    },
    {
      name: "resl-quality-mw",
      cwd: "/data/webapplication/resl_approval/Quality/backend",
      script: "server.js",
      instances: 1,
      exec_mode: "fork",
      max_memory_restart: "512M",
      env: { NODE_ENV: "production" },
      out_file: "/data/webapplication/resl_approval/Quality/logs/middleware-out.log",
      error_file: "/data/webapplication/resl_approval/Quality/logs/middleware-err.log",
      time: true,
      autorestart: true,
      restart_delay: 3000,
    },
  ],
};
```

Key options explained:

| Option | Why |
|---|---|
| `exec_mode: "fork"`, `instances: 1` | both processes are stateful enough (and cheap enough) that clustering adds risk without benefit; scale with a second server behind Nginx instead |
| `max_memory_restart` | PM2 restarts the process if it leaks past the limit |
| `time: true` | prefixes every log line with a timestamp |
| `restart_delay` / `max_restarts` | prevents a tight crash-loop from burning CPU |
| `interpreter: "none"` | `wrangler` is a binary shim, not a `.js` entry point |
| `cwd … /frontend/current` | `current` is a symlink to the active release, which is what makes rollback instant (guide 12) |

## 4. Start the applications

Do this **after** guides 07 and 08 have placed the code and `.env` files.

```bash
cd /data/webapplication/resl_approval/Quality/scripts
pm2 start ecosystem.config.cjs
pm2 status
```

Start a single app:

```bash
pm2 start ecosystem.config.cjs --only resl-quality-mw
```

## 5. Restart, reload and stop

```bash
pm2 restart resl-quality-app        # hard restart (brief downtime)
pm2 reload  resl-quality-app        # graceful; preferred after a deploy
pm2 stop    resl-quality-app
pm2 delete  resl-quality-app        # remove from the process list
pm2 restart ecosystem.config.cjs --update-env   # after changing env values
```

- **`reload`** replaces the process without dropping the listening socket
  where the app supports it — use it in `deploy.sh`.
- **`--update-env`** is required after editing `.env`; PM2 otherwise reuses the
  environment captured at first start.

## 6. View logs

```bash
pm2 logs                            # both apps, live
pm2 logs resl-quality-mw --lines 200
pm2 flush                           # truncate all PM2 logs
tail -f /data/webapplication/resl_approval/Quality/logs/app-err.log
```

## 7. Save the process list

PM2 does not remember apps across reboots unless you dump the list:

```bash
pm2 save
```

This writes `~/.pm2/dump.pm2`. Re-run it after **every** change to the process
list (add/remove/rename an app).

## 8. Configure the startup service

```bash
pm2 startup systemd -u deploy --hp /home/deploy
# It prints a `sudo env PATH=... pm2 startup ...` command — run that command
sudo systemctl enable pm2-deploy
sudo systemctl status pm2-deploy
```

Test it properly:

```bash
sudo reboot
# after it comes back
pm2 status                          # both apps online
```

To remove the boot integration later: `pm2 unstartup systemd`.

## 9. Verification checklist

```bash
pm2 status                                   # 2 apps, status "online", restarts 0
curl -sI http://127.0.0.1:3000/login         # 200
curl -s  http://127.0.0.1:3005/__health      # {"ok":true,...}
pm2 describe resl-quality-app | grep -E 'exec cwd|script path|out log'
```
