# Fix the generated `dist/start.mjs` (invalid regular expression)

## What the crash actually is

PM2 started the process and Node rejected the file at parse time:

```
SyntaxError: Invalid regular expression: missing /
```

The launcher is generated by `scripts/collect-dist.mjs` as a backtick template string. That template contains the line:

```js
for (const line of readFileSync(envFile, "utf8").split(/\r?\n/)) {
```

Inside a backtick template, `\r` and `\n` are escape sequences, so they were converted into a real carriage return and newline **before** being written to `dist/start.mjs`. The emitted file therefore contains a regex literal broken across two lines — `split(/` then a line break — which Node cannot parse. Nothing else in the deployment is wrong; the file was simply written malformed.

## Code fix (one line, one file)

In `scripts/collect-dist.mjs`, inside the `launcher` template string, escape the backslashes so the literal characters survive into the output:

```js
.split(/\\r?\\n/)
```

That is the only change. After it, `npm run build` emits a `dist/start.mjs` that parses.

## Unblock the server right now without rebuilding

You do not have to rebuild to get login working today — patch the one line in place:

```bash
cd /data/webapplication/resl_approval/Quality/frontend/dist
grep -n 'split(/' start.mjs
```

You will see the regex split across two lines. Replace those with a single correct line, then:

```bash
node --check start.mjs        # must print nothing
pm2 restart Qty_App
pm2 logs Qty_App --lines 40
```

Simplest patch, safe because the env-file loader does not need a regex at all:

```bash
python3 - <<'PY'
import re, pathlib
p = pathlib.Path("start.mjs")
s = p.read_text()
s = re.sub(r'\.split\(/\s*\r?\n?\s*/\)', '.split("\\n")', s)
p.write_text(s)
PY
node --check start.mjs
```

## Before restarting, create `dist/.env.runtime`

The server process needs its own unprefixed variables, or login will fail even once the process stays up:

```ini
PORT=8080
HOST=127.0.0.1
NODE_ENV=production
SUPABASE_URL=http://127.0.0.1:8000
SUPABASE_PUBLISHABLE_KEY=<ANON_KEY from backend/.env>
SUPABASE_ANON_KEY=<ANON_KEY from backend/.env>
SUPABASE_SERVICE_ROLE_KEY=<SERVICE_ROLE_KEY from backend/.env>
MIDDLEWARE_SHARED_SECRET=<same secret the middleware uses>
```

Also make sure `npm install` was run inside `dist/` (it pulls `wrangler`, which the launcher spawns).

## Verify

```bash
ss -ltnp | grep ':8080'                # a listener must appear

curl -i http://127.0.0.1:8080/         # any HTTP response, not "couldn't connect"
```

## Scope

One file changes in the codebase: `scripts/collect-dist.mjs`. No app, SAP, or UI logic is touched. The in-place patch above is only so you don't have to wait for a rebuild.
