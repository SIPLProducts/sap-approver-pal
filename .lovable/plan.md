# Restore login server functions on port 8080

## Confirmed request path

```text
Browser :8081/_serverFn/<hash>
  -> Nginx proxy_pass http://127.0.0.1:8080
  -> compiled TanStack app server
  -> database/auth API on 127.0.0.1:8000
  -> SAP middleware configured in the database
```

The repository’s Nginx target is correct and preserves the `/_serverFn/...` path. A **502 generated by Nginx** occurs before SAP login logic runs: Nginx cannot connect to the app server, or that process closes/crashes while handling the request.

## 1. Identify the exact upstream failure

Run on the Ubuntu server:

```bash
ss -ltnp | grep ':8080' || echo 'NOT LISTENING ON 8080'
curl -sv http://127.0.0.1:8080/ -o /dev/null
tail -n 50 /var/log/nginx/error.log
pm2 ls
pm2 logs Qty-App --lines 100 --nostream
```

Interpretation:

- `connect() failed (111: Connection refused)` + no `:8080` listener: app server is not running.
- Listener exists but `curl` resets/fails: app server is crashing; use the foreground start in step 3.
- Nginx log points to another port such as `8082`: the loaded Nginx config differs from the intended config; inspect with `nginx -T | grep -A8 'location /_serverFn/'`.
- Local `curl :8080` works but Nginx still returns 502: reload the validated Nginx configuration.

## 2. Put the required runtime files on the server

The existing `dist/` contains both static assets and `dist/server/index.mjs`, but this project starts that compiled server through `scripts/start-server.mjs` and Wrangler. Keep the client and server folders from the **same build**.

Copy from the build machine:

```bash
rsync -a --delete dist/ root@10.150.150.130:/data/webapplication/resl_approval/Quality/frontend/dist/
rsync -a package.json package-lock.json scripts/ root@10.150.150.130:/data/webapplication/resl_approval/Quality/frontend/
```

On the Ubuntu server:

```bash
cd /data/webapplication/resl_approval/Quality/frontend
node -v                         # must be Node 20+
ls -l package.json scripts/start-server.mjs dist/server/index.mjs dist/server/wrangler.json
npm ci --include=dev
npx wrangler --version
```

If `npx wrangler --version` cannot find Wrangler, install the same Wrangler version used on the build machine rather than relying on an unpinned download. The server needs network/package-registry access for installation; otherwise copy a prepared deployment directory containing the lockfile and installed runtime dependencies from a matching Linux build host.

## 3. Start in the foreground with runtime environment loaded

`VITE_*` values are browser build-time configuration. The app server separately requires unprefixed runtime variables. Load the backend file without printing secret values:

```bash
cd /data/webapplication/resl_approval/Quality/frontend
set -a
. /data/webapplication/resl_approval/Quality/backend/.env
set +a

export PORT=8080
export HOST=127.0.0.1
export NODE_ENV=production
export SUPABASE_URL=http://127.0.0.1:8000
export SUPABASE_PUBLISHABLE_KEY="$ANON_KEY"
export SUPABASE_SERVICE_ROLE_KEY="$SERVICE_ROLE_KEY"

for name in SUPABASE_URL SUPABASE_PUBLISHABLE_KEY SUPABASE_SERVICE_ROLE_KEY; do
  test -n "${!name}" && echo "$name=SET" || echo "$name=MISSING"
done

npm start
```

Expected startup line:

```text
[start] serving dist/ on http://127.0.0.1:8080
```

Do not continue until another terminal shows:

```bash
ss -ltnp | grep ':8080'
curl -i http://127.0.0.1:8080/login
```

If startup exits, the foreground stack trace is the root cause. Common fixes are a missing runtime variable, missing Wrangler, an incomplete `dist/server`, or an incompatible Node version.

## 4. Keep the server alive with PM2

After the foreground process works, stop it with Ctrl+C. Create a root-readable-only PM2 ecosystem file containing the same runtime variables, then start it. Do not paste secret values into chat or commit that file.

```javascript
// /data/webapplication/resl_approval/Quality/frontend/ecosystem.config.cjs
module.exports = {
  apps: [{
    name: "Qty-App",
    cwd: "/data/webapplication/resl_approval/Quality/frontend",
    script: "npm",
    args: "start",
    autorestart: true,
    max_restarts: 10,
    env: {
      PORT: "8080",
      HOST: "127.0.0.1",
      NODE_ENV: "production",
      SUPABASE_URL: "http://127.0.0.1:8000",
      SUPABASE_PUBLISHABLE_KEY: "<ANON_KEY from backend .env>",
      SUPABASE_SERVICE_ROLE_KEY: "<SERVICE_ROLE_KEY from backend .env>"
    }
  }]
};
```

```bash
cd /data/webapplication/resl_approval/Quality/frontend
chmod 600 ecosystem.config.cjs
pm2 delete Qty-App 2>/dev/null || true
pm2 start ecosystem.config.cjs
pm2 save
pm2 startup                    # run the command PM2 prints, once
pm2 ls
pm2 logs Qty-App --lines 50 --nostream
ss -ltnp | grep ':8080'
```

## 5. Verify and reload Nginx

The required blocks are:

```nginx
location /_serverFn/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    proxy_read_timeout 300s;
}

location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_http_version 1.1;
    proxy_read_timeout 300s;
}
```

Validate what Nginx actually loaded, then reload:

```bash
nginx -T | grep -A10 'location /_serverFn/'
nginx -t && systemctl reload nginx
```

Test the real path through Nginx by retrying login in the browser while watching both logs:

```bash
tail -f /var/log/nginx/error.log
pm2 logs Qty-App
```

Once the app server is reachable, login failures will change from Nginx `502` to an application response. That next response identifies any remaining SAP configuration, shared-secret, or credential issue.

## 6. Correct the browser auth URL in the next build

Because port `8000` is private to the server, build the frontend with:

```text
VITE_SUPABASE_URL=http://10.150.150.130:8081/supabase
VITE_SUPABASE_PUBLISHABLE_KEY=<exact ANON_KEY from backend .env>
```

Then rebuild and copy the **entire matching `dist/`**. This is independent of the 502 fix but is required for the browser to establish the session after SAP accepts the login.

## Success criteria

- `ss` shows a listener on `127.0.0.1:8080`.
- PM2 shows `Qty-App` online without a restart loop.
- A request to `/_serverFn/<hash>` appears in the app-server log, not as `connect() failed` in Nginx.
- The browser uses `/supabase` through port `8081`, not direct port `8000`.
- SAP login returns an application result and creates the browser session.
